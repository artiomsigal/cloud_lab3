# ADR-0002. Размещение базы данных

- Статус: принято
- Дата: 24.11.2026

## Контекст

В лабораторной работе №2 приложение и база данных размещались на одном сервере. В лабораторной работе №3 необходимо разделить приложение и базу данных, повысить безопасность инфраструктуры и ограничить доступ к PostgreSQL из интернета. При этом необходимо учитывать стоимость используемых ресурсов AWS и возможность установки обновлений.

## Решение

Было принято решение разместить базу данных PostgreSQL на отдельном EC2-экземпляре в приватной подсети private-a (10.24.10.0/24).

Сервер базы данных не имеет публичного IP-адреса. Приложение подключается к базе данных через приватную сеть по порту 5432. Доступ ограничивается правилами Security Group и файлом pg_hba.conf. Административный доступ осуществляется через bastion.

## Рассмотренные альтернативы

1. **База данных на одном сервере с приложением.** Преимуществами являются простота настройки и минимальные расходы. От данного варианта отказались из-за отсутствия сетевой изоляции и совместного использования вычислительных ресурсов.

2. **База данных на отдельном сервере в публичной подсети.** Такой вариант позволяет разделить ресурсы приложения и базы данных, но при наличии публичного IP повышается риск несанкционированного доступа из интернета.

3. **База данных на отдельном сервере в приватной подсети.** Данный вариант обеспечивает сетевую изоляцию базы данных и позволяет ограничить доступ к ней. Недостатком является необходимость дополнительной настройки доступа в интернет для установки обновлений. Этот вариант был выбран для реализации.

## Последствия

Повышается безопасность базы данных, обеспечивается разделение вычислительных ресурсов и ограничивается доступ из внешней сети. При этом усложняется настройка инфраструктуры и появляются расходы на отдельный EC2-экземпляр. Отказ единственного сервера базы данных по-прежнему приводит к её недоступности.

Для установки пакетов и обновлений безопасности используется временный NAT Gateway. После завершения обновлений шлюз удаляется, маршрут удаляется из таблицы маршрутизации, а Elastic IP освобождается. Стоимость складывается из времени работы NAT Gateway, объёма обработанного трафика и стоимости публичного IPv4-адреса. Ориентировочная стоимость одного часа работы шлюза в регионе eu-central-1 составляет около 0,052 доллара без учёта трафика и публичного IPv4-адреса.

Elastic IP сервера app-server обеспечивает постоянный публичный IP-адрес, который не изменяется после остановки и повторного запуска экземпляра. После добавления балансировщика нагрузки пользователи будут обращаться к его DNS-имени, а сервер приложения сможет размещаться в приватной подсети без собственного Elastic IP.
